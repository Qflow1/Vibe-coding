## 一、一句话定位

> **一款人生模拟游戏。玩家挑一个起点，在一个架空的时代里，为一个普通人（或大人物）的一生做出选择；每个选择改变数值，数值加上随机性决定下一个岔路口 —— 没有标准结局，只有「你活成了谁」。**

### 它不是什么

| | |
|---|---|
| **不是《钢铁雄心》** | 那是**国家推演**，玩家操纵的是地图、军队、外交。本作操纵的是**一个人**，地图只是背景 |
| **不是视觉小说** | 视觉小说是线性的：选 A 或选 B，看对应剧情，走到预设结局。本作是**系统性的**：选择改的是数值，下一个节点由数值算出来 |
| **不是爽游** | 目标不是"变强""通关"，是"**经历**"。一局结束时不是"我赢了"，是"我成了这样一个人" |

### 核心张力

> **一局开始时，你可能什么都不是，也可能一开局就站在高处。但两者都不保证结局。**

这是整个游戏最迷人、也最难做好的地方。

## 二、游戏名

| | |
|---|---|
| **中文名** | 无名之辈 |
| **英文名** | **NOBODY** |
| **目录名** | `Nobody` |

### 为什么是这个词

英文里有一组天然对照：

- `a nobody` = 无名小卒、不起眼的人
- `a somebody` = 有头有脸的人物、人物

**这两个词正好是这款游戏的两端。** 玩家可以在两端之间移动，也可能一辈子没挪动过 —— 一个名字把整款游戏说完了。

### 暂定宣传语

> **Everyone starts as a nobody. Not everyone stays one.**
> 每个人都从无名之辈开始，但不是每个人都一直无名。

## 三、目标玩家

| 项目 | 内容 |
|---|---|
| **谁** | 喜欢「叙事型」和「模拟经营」类游戏的人；对"选择与后果"这件事有兴趣的人；爱看故事但不想练操作的人 |
| **什么时候玩** | 碎片时间。一局 15–30 分钟，也适合反复重开 |
| **他们真正想要的** | **不是胜利，是「如果」** —— "如果我当年没去那座城市会怎样" |
| **他们不要什么** | 不要手速、不要复杂操作、不要上来先学一百个按钮 |

### 非目标玩家

- 想要"打怪升级爽感"的人 → 本作给不了
- 想要"挑战操作、追求高分"的人 → 本作没有排行榜
- 想要"一次通关就结束"的人 → 本作的乐趣在**反复重开**

## 四、核心循环（发动机）

```flow
数据流图 · 一局游戏的一生

[1] 选起点
    背景 / 家庭 / 年代 / 初始数值
         ↓
[2] 遇到人生节点
    升学 / 求职 / 恋爱 / 婚姻 / 变故 / 时代事件（征兵令、经济危机…）
         ↓
[3] 做选择
    2–4 个选项，每个都有代价，没有"全都要"
         ↓
[4] 数值变化
    健康 / 金钱 / 心情 / 关系 / 名声 / 能力
         ↓
[5] 数值 + 随机权重 → 决定下一个节点是什么
         ↓
    回到 [2]，循环，直到进入结局
         ↓
[6] 结算：「你活成了谁」
```

### 这个循环拆开，只有四块积木

| # | 积木 | 它管什么 |
|---|---|---|
| 1 | **节点（Node）** | 一个场景：一段文本 + 若干个选项。这是游戏的内容单位 |
| 2 | **选项（Choice）** | 有**前置条件**（"已婚才显示"）+ 有**后果**（改哪些数值、跳到哪儿） |
| 3 | **数值（Stats）** | 一组数字，代表这个人此刻的状态 |
| 4 | **权重（Weight）** | 决定"接下来会发生什么"的概率 |

> **整个游戏，就是这四样东西的不同组合。**
> 这句话很重要 —— 因为它是"一个人也能做出来"的理论依据。如果只有四块积木，那它就不是一个无底洞。

## 五、参照物研究

按 Day 3 学的方法，看四个"近亲"，各自学到什么。

### ① BitLife（现实向人生模拟，2018，Candywriter）

| 项目 | 内容 |
|---|---|
| **它是什么** | 纯文本 + 按钮的人生模拟。从出生开始（随机国家、性别、家庭），每年做选择，直到死亡 |
| **它做对了什么** | ① 门槛极低：打开就能玩，没有教程 ② **随机事件的幽默感**：荒诞事件让人忍不住截图分享 ③ **重开欲望强**："这次我要当个好人" |
| **它做砸了什么** | 选择深度浅（大量是"是/否"二选一）／后期重复感明显／**没有"世界"，只有事件流** —— 所有事都发生在你身上，你影响不了任何东西 |
| **给本作的启示** | **极简交互是对的**。但也证明：**只有事件流、没有世界感，会腻。** 这是本作必须超越它的地方 |

### ② 太吾绘卷（国产武侠世代模拟，2018，螺舟）

| 项目 | 内容 |
|---|---|
| **它是什么** | 武侠世界 + **世代传承**：你死了，儿子接着，一代一代传下去 |
| **它做对了什么** | ① **世界有自己的规则**：NPC 之间有关系网，会自己行动、自己结仇和联姻 ② 世代传承带来**史诗感** —— 你不再是一个人，是一条血脉 |
| **它做砸了什么** | **系统过于复杂，新手劝退**（出了名的）；UI 晦涩，很多玩家玩了几十小时还在查攻略 |
| **给本作的启示** | ① 「世界感」值得学 ② **但复杂度要狠狠砍** —— 本作第一版绝不做 NPC 关系网 |
|  | ③ "传承"这个机制很好，**可以进路线图**（第一版不做） |

### ③ 十字军之王 3（Paradox，2020）

| 项目 | 内容 |
|---|---|
| **它是什么** | 中世纪贵族家族模拟 + 大战略地图。你要扮演一个贵族，人生、婚姻、子女、阴谋、战争都发生在一张世界地图上 |
| **它做对了什么** | ① 它是**唯一一个真正把"大战略地图"和"个人一生的选择"缝在一起还缝成功**的商业游戏 ② 角色的**性格特质会真的影响行为**，于是"故事自己长出来" ③ 玩完一局能讲出一个故事来 —— 这个体验极珍贵 |
| **它做砸了什么** | ① **系统庞大到需要看视频才能入门** ② DLC 众多，全买价格不菲 |
| **给本作的启示** | ① 它证明了"**个人选择 + 时代背景**"这条路是通的，有商业成功先例 ② 它也证明了**这条路的天花板需要工业级投入** —— 所以本作必须**只取它的灵魂，不取它的体量**：不做地图、不做军队、不做外交，只做"一个人 + 时代压力" |

### ④ 钢铁雄心 4（Paradox，2016）—— 最初的参照物

| 项目 | 内容 |
|---|---|
| **它是什么** | 二战背景的**国家推演**游戏。玩家控制一个国家：工业、军队、外交、战线 |
| **它做对了什么** | 历史推演感极强，玩家能真切感受到"世界在你手下转动" |
| **它做砸了什么** | ❌ **和"个人命运"完全无关** —— 它里面没有"人"，只有师团、产能和省份 |
| **给本作的启示** | 🔑 **这是最重要的一条**：本作最初的想法是"和钢铁雄心差不多，但是架空历史"，**但推演下去会发现两者的核心完全不同**。真正想做的不是"推演一个国家"，是"**看一个人怎么活**"。历史只是压力的来源 |
|  | 所以：**钢铁雄心是错的参照物**，它提供的是"时代感"的灵感，不是玩法模板 |

## 六、关键设计决策

### 6.1 起点差异怎么设计

**这是本作最能立住的地方**（原话：「有的人职位很高，有的人终其一生只是一个普通人」）。

起点差异有**两种做法**，代价差别巨大：

| | **做法一：起点 = 一组初始数值 + 一个出身标签** ⭐ | 做法二：每个出身 = 一整条专属剧情线 |
|---|---|---|
| 怎么做 | 出身只是"开局时的数值不同 + 少量专属节点" | 每类人都有自己的完整故事 |
| 好处 | **可组合、可扩展**：加一个新出身，只需要写一小份配置 | 每条线都精致 |
| 代价 | 同一个节点，不同出身的人看到时反应不同 —— 需要写"分支文本" | **工作量是做法一的十倍以上** |
| 第一版 | ✅ **做这个** | ❌ 不做 |

**第一版的出身清单（草案，待定）**：

| 出身 | 起手的差别（描述，不是最终数值） |
|---|---|
| 普通家庭 | 各项平庸，没有资源，也没有包袱 |
| 优渥家庭 | 钱和资源多，但"该走的路"被安排好了 |
| 贫困家庭 | 起点低，但"往上走"的欲望值高 |
| 小城青年 | 关系简单，机会少 |
| 大城市青年 | 机会多，但压力大 |

> ⚠️ **重要设计原则**：**强起点不等于好结局。**
> 从"优渥家庭"开始，玩家会失去"自己挣来的"那种体验；从"贫困家庭"开始，也可能因为吃过苦而有更强的韧性。
> **如果高起点直接等于赢，这个游戏就变成了一个"选难度"菜单，而不是"命运"。**

### 6.2 随机性怎么调（最容易翻车的地方）

**随机性是一条很细的线**：

```
全是随机  ←───────────────┼───────────────→  完全不随机
玩家感觉"我说了不算"        甜点区        玩家感觉"这是剧本，不是游戏"
```

**两条设计红线**：

1. **选择必须真的有用** —— 每个选择至少要影响一个数值。如果玩家做 5 个选择都没感到变化，他会放弃
2. **后果要能追溯到选择** —— 结算时应该能让玩家看到"因为当年选了 X，所以后面发生了 Y"。**这是本作最珍贵的情感时刻**

**一个具体的机制设想（待验证）**：

> 「回声」：人生后半段的某些节点，会引用前半段的某个选择。
> 例：你 20 岁时选了"留在小城陪父母"，40 岁时会收到一个节点，提示你"当年的老同学如今在外地做成了事"。
> **技术上不复杂（只是记录几个标记位），情感效果极强。**

### 6.3 世界观为什么必须"可插拔"（创意工坊的技术本质）

**提出了一个新想法：做创意工坊，让玩家自由选择世界背景、补充设定。**

这件事要拆成两半看 —— 一半现在就能拿到，一半是很远的事。

#### 🔑 真正重要的那一半：它倒逼出一个好结构

创意工坊的核心不是"做一个平台"，而是一个**设计原则**：

> **从第一行代码起，就把「内容」和「引擎」彻底分开。**
>
> - **内容**（剧情文本、人物、数值配置、世界设定）→ 放在**数据文件**里，可以整个替换
> - **引擎**（读取、判断、跳转、计算、显示）→ 放在**代码**里，不因内容改变而改动

**这个结构带来两个直接好处**：

| 好处 | 说明 |
|---|---|
| **① 玩家想加一个新世界 → 只需要写一份数据文件，不碰代码** | 这就是"玩家选择世界背景"的技术基础 |
| **② 你自己写新剧情 → 也只需要写数据，不用改代码** | 内容产出速度快好几倍 —— 而"内容量"正是本作最难的部分之一（见 6.4） |

> 这和「今日热搜」网站里那条约定是**同一个思想**：*「取数只写在一个地方」* ——
> 把易变的东西集中到一个地方，将来改它只需要改一处。
> **只是它现在用在了游戏上，价值更大。**

**而且它的成本是零。** 这不是"多做一件事"，是"换个习惯写代码"。第一版就该这么做。

#### ⏳ 另一半：真正的创意工坊平台，是很远的事

| 真创意工坊需要什么 | 现在有吗 |
|---|---|
| 模组格式规范（规定别人的文件长什么样、怎么校验） | ❌ 需要先有稳定的游戏本体才能定 |
| 模组加载机制 | ❌ |
| 存储与分享（上传、下载、列表、搜索） | ❌ 需要后端 + 服务器 |
| 审核机制（防违规内容 —— 这类游戏的内容风险不低） | ❌ |
| 版本兼容（游戏更新了，老模组还能用吗） | ❌ 这是最麻烦的一个 |

> **判断**：创意工坊是**平台级功能，不是游戏功能**。它排在路线图的最后一段 —— **游戏本身得先成立，才谈得上让别人给它做内容。**

### 6.4 内容从哪来（最容易低估的问题）

**这是本作最大的风险，而且它不是技术问题。**

一局 20 分钟，玩家大概会遇到 **15–25 个节点**。如果重开 5 次还不腻，至少需要 **60–80 个不重复的节点**。要真正耐玩，需要几百个。

**写一个节点要多久？** 一段 100 字的文本 + 2–4 个选项 + 每个选项的后果 —— 认真写一个，半小时。**80 个节点 = 40 小时纯写作**，还不算调平衡。

**三条可能的出路**（都要在未来验证）：

| 出路 | 说明 | 风险 |
|---|---|---|
| **① 节点池 + 随机组合** | 节点不完全串成线，而是从池子里按条件抽取 → **80 个节点能组合出远超 80 条的体验** | 可能让故事显得散 |
| **② 只做一个时代、一种人生** | 不做"从古到今的所有人"，只做"某个年代的一类人" | 内容量小了，但也牺牲了广度 |
| **③ 让玩家贡献内容** | 就是创意工坊 —— 长期看这是唯一能真正解决内容量的办法 | 需要平台，很远 |

> **第一版选 ① + ②：节点池 + 收窄到一个时代的一种人生。**
> 这也是"一个人做得出来"的前提。

### 6.5 世代传承（记入路线图，第一版不做）

太吾绘卷最动人的机制：你死了，你的孩子接着，血脉一代代传下去。

**它为什么好**：把"一个人的一生"变成"一个家族的历史"，情感厚度立刻翻倍。

**为什么第一版不做**：它要求"上一代的数值和选择会影响下一代"（遗传、家产、名声），这是**在核心循环上再加一层循环**。地基还没打好就盖二楼。

## 七、技术门槛清单（需要会什么）

诚实评估：**这是四个作品里最大的一个**，比三个网站加起来都大。

| # | 要会的 | 用来干什么 | 现在会吗 |
|---|---|---|---|
| 1 | **HTML / CSS** | 界面：文字区、选项按钮、数值面板 | 28 天课程会学 |
| 2 | **JavaScript** | 核心：读取节点、判断条件、跳转、算数值 | 28 天课程会学（本作的命脉） |
| 3 | **数据结构设计** | 剧情节点怎么组织成文件（这是**设计**能力，不是语法） | ❌ 课程不教，要靠练 |
| 4 | **状态管理** | 玩家数值、进度、标记位怎么存、怎么在界面间传递 | ⚠️ 课程只碰一点 |
| 5 | **条件与权重逻辑** | "如果健康<30 且已婚则显示选项 C"、概率抽取 | ⚠️ 需要额外学 |
| 6 | **存档机制** | 保存这一局，下次接着玩 | 课程数据库阶段会碰 |
| 7 | **内容创作能力** | 写剧情文本、设计选择与后果 | ❌ 不是技术问题，是**写作问题** |
| 8 | **数值平衡** | 让"强起点不一定赢"真的成立 | ❌ 只能靠反复试玩调 |

### 量级判断

| | 三个网站（合计） | 本作第一版 |
|---|---|---|
| 代码行数 | 可能 1000 行以内 | 逻辑部分可能 500–1500 行 |
| 主要难度 | 页面布局、交互 | **数据结构 + 内容量 + 平衡** |
| 卡点类型 | "这个语法不会" | **"这个设计想不清楚"** |

> **关键差别**：网站的难点是**技术**，游戏的难点是**设计**。
> 技术不会可以查，设计想不清楚 —— 查不到答案，只能自己想。

## 八、第一版（MVP）设想

**前提：这份设想只是"存档"，不是"计划" —— 什么时候做，见第九节。**

| 项目 | 第一版做什么 |
|---|---|
| **页面** | **1 个页面**：上方数值面板 / 中间文本区 / 下方选项按钮 |
| **时代** | **只做一个时代**（待定）的一种人生 |
| **出身** | 3–5 种，只影响初始数值 + 少量专属节点 |
| **节点数** | 40–60 个，用"节点池 + 条件抽取"组合 |
| **数值** | 6 个：健康 / 金钱 / 心情 / 关系 / 名声 / 能力 |
| **随机** | 有权重，但**关键节点必出现**（不能随机掉人生大事） |
| **存档** | 一个存档位，能接着玩 |
| **结算** | 结尾给一段"你的一生"总结 + 引用若干关键选择（回声机制） |
| **界面** | 纯文字 + 按钮，**不做图片、不做动画、不做音效** |
| **技术** | 与「今日热搜」同样的路线：HTML + CSS + 原生 JS，数据放数据文件（**内容与引擎分离**） |
| **成功标准** | **玩一次 15 分钟，能玩出 3 种明显不同的结局，并且想再开一局** |

### 第一版绝对不做的事

| 不做 | 为什么 |
|---|---|
| 创意工坊 / 模组系统 | 平台级功能，需要游戏本体先稳定 |
| 世代传承 | 在核心循环上再加一层循环，地基不够 |
| NPC 关系网、世界自己运转 | 太吾绘卷和 CK3 都证明这是工业级投入 |
| 地图、军队、外交 | 那是《钢铁雄心》，不是本作 |
| 多时代、多国家、多文明 | 内容量爆炸，一个人写不完 |
| 图片、立绘、动画、音效 | 第一版要验证的是**玩法**，不是美术 |
| 账号、云存档、排行榜 | 需要后端 |
| 移动端适配 | 先把桌面版做透 |
| 多语言 | 同上 |

## 十、不确定信息（哪些是拍脑袋的）

按老规矩，如实标注 —— 这些结论**没有依据**，将来动手前要重新验证。

| # | 不确定的事 | 现在凭什么这么写 |
|---|---|---|
| 1 | **40–60 个节点够不够玩 5 局不腻** | 纯估计，没有任何测试依据 |
| 2 | "一局 15–30 分钟"是否合理 | 参照 BitLife，但本作节点更重，可能偏长 |
| 3 | "6 个数值"是否合适 | 凭感觉。太少没深度，太多调不动 |
| 4 | 玩家真的愿意**反复重开**吗 | 这是整个设计的地基假设，**完全未验证** |
| 5 | 一个人能写出多少剧情文本而不崩溃 | 未知。**这是最大的风险** |
| 6 | 「回声」机制的实际效果 | 设想很动人，但没试过，可能玩家根本注意不到 |
| 7 | 强起点与好结局如何平衡 | 只提了原则（"强起点≠好结局"），**具体怎么调完全没有方案** |
| 8 | 三个参照游戏的评价是否准确 | 来自公开资料与个人印象，未逐个深入试玩 |
| 9 | 创意工坊的模组格式该怎么定 | 没有现成先例可抄，需要专门研究 |
| 10 | 这款游戏是否真的"一个人做得出来" | **诚实地说：不知道。** 这份文档的作用之一，就是将来用它来回答这个问题 |
