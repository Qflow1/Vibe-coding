## 一、一句话定位

> **一款人生模拟游戏。玩家挑一个起点，在一个架空的时代里，为一个普通人（或大人物）的一生做出选择；每个选择改变数值，数值加上随机性决定下一个岔路口 —— 没有标准结局，只有「你活成了谁」。**

### 它不是什么

| | |
|---|---|
| **不是《钢铁雄心》** | 那是**国家推演**，玩家操纵的是地图、军队、外交。本作操纵的是**一个人**，地图只是背景 |
| **不是视觉小说** | 视觉小说是线性的：选 A 或选 B，看对应剧情，走到预设结局。本作是**系统性的**：选择改的是数值，下一个节点由数值算出来。⚠️ 注意这里的"不是"说的是**剧情结构**，不是"不许有画面" —— **表现层完全可以借用视觉小说的演出手法**（见第十三节） |
| **不是爽游** | 目标不是"变强""通关"，是"**经历**"。一局结束时不是"我赢了"，是"我成了这样一个人" |

### 核心张力

> **一局开始时，你可能什么都不是，也可能一开局就站在高处。但两者都不保证结局。**

这是整个游戏最迷人、也最难做好的地方。

### 它最终想成为什么：地球 online

**这是这个想法真正的出发点。**

> 原话：「这是我最想做的了，我常常称其为**地球 online**，虽然目前做不到这种程度。」

「地球 online」这个词比"人生模拟游戏"更准 —— 现实人生本来就长得像一场大型多人在线游戏。但要把它**拆成两半**看，因为其中一半是陷阱，另一半才是真正想要的东西：

| | **不值钱的那半** | **值钱的那半** ⭐ |
|---|---|---|
| **是什么** | 世界有多大 | **选择的重量** |
| **内容** | 70 亿人同时行动，经济、政治、气候全联动 | 不能读档、不能预知、多年后才知道当初那一步意味着什么 |
| **需要什么** | 国家级算力 | **40 个节点 + 时间跨度** |
| **结论** | ❌ 做不出来，**也不必做** | ✅ **这就是本作要抓的东西** |

**为什么"世界规模"那半不必追**：《模拟人生》把世界做得再细，玩家记住的还是"**我那个小人干了什么**"。
**规模不产生情感，选择才产生情感。**

#### 「真」只需要三个条件 —— 而且都已经写在文档里了

| "地球 online" 的真 | 对应的已有设计 |
|---|---|
| 选择有代价，没有"全都要" | 第四节核心循环：「每个选项都有代价」 |
| 后果能追溯到选择 | 6.2 红线②：「结算时能让玩家看到『因为当年选了 X，所以后面发生了 Y』」 |
| 不能撤销、不能预知 | 6.1 起点设计 + 6.2「回声」机制 |

> **所以不需要为"地球 online"新增任何设计 —— 只需要守住这三条。**
> 规模可以慢慢长；**这三条一破，再大的规模也不像人生。**

#### 现实里最像"地球 online"的时刻

往往不是宏大事件，而是：

> **你 22 岁那年做的一个普通决定，30 岁才发现它决定了一生。**

这个效果靠的是**回声机制 + 时间跨度**，不是世界规模。

#### 没有游戏真的模拟了人生

"目前做不到这种程度"这句判断是清醒的，但可以放宽心 ——
**没有任何一款人生模拟游戏真的模拟了人生**，四个参照物全都是近似。区别只在于**抓住了哪一部分的真实**：

| 游戏 | 抓住了什么 |
|---|---|
| BitLife | **荒诞感** —— 随机事件让人忍不住截图分享 |
| 太吾绘卷 | **血脉** —— 你死了，儿子接着，一代代传下去 |
| 十字军之王 3 | **性格** —— 特质真的影响行为，故事自己长出来 |
| **本作（目标）** | **选择的重量** —— 后果能追溯到当初那一步 |

> **不用追"全"，追"真"。**

## 二、游戏名

| | |
|---|---|
| **中文名** | 无名之辈 |
| **英文名** | **NOBODY** |
| **目录名** | `Nobody` |

### 为什么是这个词

英文里有一组天然对照：

- `a nobody` = 无名小卒、不起眼的人
- `a somebody` = 有头有脸的人物、人物

**这两个词正好是这款游戏的两端。** 玩家可以在两端之间移动，也可能一辈子没挪动过 —— 一个名字把整款游戏说完了。

### 暂定宣传语

> **Everyone starts as a nobody. Not everyone stays one.**
> 每个人都从无名之辈开始，但不是每个人都一直无名。

## 三、目标玩家

| 项目 | 内容 |
|---|---|
| **谁** | 喜欢「叙事型」和「模拟经营」类游戏的人；对"选择与后果"这件事有兴趣的人；爱看故事但不想练操作的人 |
| **什么时候玩** | 碎片时间。一局 15–30 分钟，也适合反复重开 |
| **他们真正想要的** | **不是胜利，是「如果」** —— "如果我当年没去那座城市会怎样" |
| **他们不要什么** | 不要手速、不要复杂操作、不要上来先学一百个按钮 |

### 非目标玩家

- 想要"打怪升级爽感"的人 → 本作给不了
- 想要"挑战操作、追求高分"的人 → 本作没有排行榜
- 想要"一次通关就结束"的人 → 本作的乐趣在**反复重开**

## 四、核心循环（发动机）

```flow
数据流图 · 一局游戏的一生

[1] 选起点
    背景 / 家庭 / 年代 / 初始数值
         ↓
[2] 遇到人生节点
    升学 / 求职 / 恋爱 / 婚姻 / 变故 / 时代事件（征兵令、经济危机…）
         ↓
[3] 做选择
    2–4 个选项，每个都有代价，没有"全都要"
         ↓
[4] 数值变化
    健康 / 金钱 / 心情 / 关系 / 名声 / 能力
         ↓
[5] 数值 + 随机权重 → 决定下一个节点是什么
         ↓
    回到 [2]，循环，直到进入结局
         ↓
[6] 结算：「你活成了谁」
```

### 这个循环拆开，只有四块积木

| # | 积木 | 它管什么 |
|---|---|---|
| 1 | **节点（Node）** | 一个场景：一段文本 + 若干个选项。这是游戏的内容单位 |
| 2 | **选项（Choice）** | 有**前置条件**（"已婚才显示"）+ 有**后果**（改哪些数值、跳到哪儿） |
| 3 | **数值（Stats）** | 一组数字，代表这个人此刻的状态 |
| 4 | **权重（Weight）** | 决定"接下来会发生什么"的概率 |

> **整个游戏，就是这四样东西的不同组合。**
> 这句话很重要 —— 因为它是"一个人也能做出来"的理论依据。如果只有四块积木，那它就不是一个无底洞。

## 五、参照物研究

按 Day 3 学的方法，看四个"近亲"，各自学到什么。

### ① BitLife（现实向人生模拟，2018，Candywriter）

| 项目 | 内容 |
|---|---|
| **它是什么** | 纯文本 + 按钮的人生模拟。从出生开始（随机国家、性别、家庭），每年做选择，直到死亡 |
| **它做对了什么** | ① 门槛极低：打开就能玩，没有教程 ② **随机事件的幽默感**：荒诞事件让人忍不住截图分享 ③ **重开欲望强**："这次我要当个好人" |
| **它做砸了什么** | 选择深度浅（大量是"是/否"二选一）／后期重复感明显／**没有"世界"，只有事件流** —— 所有事都发生在你身上，你影响不了任何东西 |
| **给本作的启示** | **极简交互是对的**。但也证明：**只有事件流、没有世界感，会腻。** 这是本作必须超越它的地方 |

### ② 太吾绘卷（国产武侠世代模拟，2018，螺舟）

| 项目 | 内容 |
|---|---|
| **它是什么** | 武侠世界 + **世代传承**：你死了，儿子接着，一代一代传下去 |
| **它做对了什么** | ① **世界有自己的规则**：NPC 之间有关系网，会自己行动、自己结仇和联姻 ② 世代传承带来**史诗感** —— 你不再是一个人，是一条血脉 |
| **它做砸了什么** | **系统过于复杂，新手劝退**（出了名的）；UI 晦涩，很多玩家玩了几十小时还在查攻略 |
| **给本作的启示** | ① 「世界感」值得学 ② **但复杂度要狠狠砍** —— 本作第一版绝不做 NPC 关系网 |
|  | ③ "传承"这个机制很好，**可以进路线图**（第一版不做） |

### ③ 十字军之王 3（Paradox，2020）

| 项目 | 内容 |
|---|---|
| **它是什么** | 中世纪贵族家族模拟 + 大战略地图。你要扮演一个贵族，人生、婚姻、子女、阴谋、战争都发生在一张世界地图上 |
| **它做对了什么** | ① 它是**唯一一个真正把"大战略地图"和"个人一生的选择"缝在一起还缝成功**的商业游戏 ② 角色的**性格特质会真的影响行为**，于是"故事自己长出来" ③ 玩完一局能讲出一个故事来 —— 这个体验极珍贵 |
| **它做砸了什么** | ① **系统庞大到需要看视频才能入门** ② DLC 众多，全买价格不菲 |
| **给本作的启示** | ① 它证明了"**个人选择 + 时代背景**"这条路是通的，有商业成功先例 ② 它也证明了**这条路的天花板需要工业级投入** —— 所以本作必须**只取它的灵魂，不取它的体量**：不做地图、不做军队、不做外交，只做"一个人 + 时代压力" |

### ④ 钢铁雄心 4（Paradox，2016）—— 最初的参照物

| 项目 | 内容 |
|---|---|
| **它是什么** | 二战背景的**国家推演**游戏。玩家控制一个国家：工业、军队、外交、战线 |
| **它做对了什么** | 历史推演感极强，玩家能真切感受到"世界在你手下转动" |
| **它做砸了什么** | ❌ **和"个人命运"完全无关** —— 它里面没有"人"，只有师团、产能和省份 |
| **给本作的启示** | 🔑 **这是最重要的一条**：本作最初的想法是"和钢铁雄心差不多，但是架空历史"，**但推演下去会发现两者的核心完全不同**。真正想做的不是"推演一个国家"，是"**看一个人怎么活**"。历史只是压力的来源 |
|  | 所以：**钢铁雄心是错的参照物**，它提供的是"时代感"的灵感，不是玩法模板 |

### 四个产品横向对比

| | BitLife | 太吾绘卷 | 十字军之王 3 | 钢铁雄心 4 | **本作（目标）** |
|---|---|---|---|---|---|
| 玩家操纵什么 | 一个人 | 一个家族 | 一个家族 + 地图 | 一个国家 | **一个人** |
| 世界会自己跑吗 | 不会 | 会 | 会 | 会 | **不必** |
| 时代的角色 | 几乎没有 | 背景 | 强 | 核心 | **压力的来源** |
| 上手难度 | 极低 | 极高 | 高 | 高 | **低（目标）** |
| 一局时长 | 10–30 分 | 几十小时 | 几十小时 | 几十小时 | **15–30 分** |
| 重开欲望 | 强 | 中 | 强 | 中 | **强（目标）** |
| 一个人做得出来吗 | 接近可以 | ❌ | ❌ | ❌ | **瞄准这个** |

## 六、关键设计决策

### 6.1 起点差异怎么设计

**这是本作最能立住的地方**（原话：「有的人职位很高，有的人终其一生只是一个普通人」）。

起点差异有**两种做法**，代价差别巨大：

| | **做法一：起点 = 一组初始数值 + 一个出身标签** ⭐ | 做法二：每个出身 = 一整条专属剧情线 |
|---|---|---|
| 怎么做 | 出身只是"开局时的数值不同 + 少量专属节点" | 每类人都有自己的完整故事 |
| 好处 | **可组合、可扩展**：加一个新出身，只需要写一小份配置 | 每条线都精致 |
| 代价 | 同一个节点，不同出身的人看到时反应不同 —— 需要写"分支文本" | **工作量是做法一的十倍以上** |
| 第一版 | ✅ **做这个** | ❌ 不做 |

**第一版的出身清单（草案，待定）**：

| 出身 | 起手的差别（描述，不是最终数值） |
|---|---|
| 普通家庭 | 各项平庸，没有资源，也没有包袱 |
| 优渥家庭 | 钱和资源多，但"该走的路"被安排好了 |
| 贫困家庭 | 起点低，但"往上走"的欲望值高 |
| 小城青年 | 关系简单，机会少 |
| 大城市青年 | 机会多，但压力大 |

> ⚠️ **重要设计原则**：**强起点不等于好结局。**
> 从"优渥家庭"开始，玩家会失去"自己挣来的"那种体验；从"贫困家庭"开始，也可能因为吃过苦而有更强的韧性。
> **如果高起点直接等于赢，这个游戏就变成了一个"选难度"菜单，而不是"命运"。**

### 6.2 随机性怎么调（最容易翻车的地方）

**随机性是一条很细的线**：

```
全是随机  ←───────────────┼───────────────→  完全不随机
玩家感觉"我说了不算"        甜点区        玩家感觉"这是剧本，不是游戏"
```

**两条设计红线**：

1. **选择必须真的有用** —— 每个选择至少要影响一个数值。如果玩家做 5 个选择都没感到变化，他会放弃
2. **后果要能追溯到选择** —— 结算时应该能让玩家看到"因为当年选了 X，所以后面发生了 Y"。**这是本作最珍贵的情感时刻**

**一个具体的机制设想（待验证）**：

> 「回声」：人生后半段的某些节点，会引用前半段的某个选择。
> 例：你 20 岁时选了"留在小城陪父母"，40 岁时会收到一个节点，提示你"当年的老同学如今在外地做成了事"。
> **技术上不复杂（只是记录几个标记位），情感效果极强。**

### 6.3 世界观为什么必须"可插拔"（创意工坊的技术本质）

**提出了一个新想法：做创意工坊，让玩家自由选择世界背景、补充设定。**

这件事要拆成两半看 —— 一半现在就能拿到，一半是很远的事。

#### 🔑 真正重要的那一半：它倒逼出一个好结构

创意工坊的核心不是"做一个平台"，而是一个**设计原则**：

> **从第一行代码起，就把「内容」和「引擎」彻底分开。**
>
> - **内容**（剧情文本、人物、数值配置、世界设定）→ 放在**数据文件**里，可以整个替换
> - **引擎**（读取、判断、跳转、计算、显示）→ 放在**代码**里，不因内容改变而改动

**这个结构带来两个直接好处**：

| 好处 | 说明 |
|---|---|
| **① 玩家想加一个新世界 → 只需要写一份数据文件，不碰代码** | 这就是"玩家选择世界背景"的技术基础 |
| **② 你自己写新剧情 → 也只需要写数据，不用改代码** | 内容产出速度快好几倍 —— 而"内容量"正是本作最难的部分之一（见 6.4） |

> 这和「今日热搜」网站里那条约定是**同一个思想**：*「取数只写在一个地方」* ——
> 把易变的东西集中到一个地方，将来改它只需要改一处。
> **只是它现在用在了游戏上，价值更大。**

**而且它的成本是零。** 这不是"多做一件事"，是"换个习惯写代码"。第一版就该这么做。

#### ⏳ 另一半：真正的创意工坊平台，是很远的事

| 真创意工坊需要什么 | 现在有吗 |
|---|---|
| 模组格式规范（规定别人的文件长什么样、怎么校验） | ❌ 需要先有稳定的游戏本体才能定 |
| 模组加载机制 | ❌ |
| 存储与分享（上传、下载、列表、搜索） | ❌ 需要后端 + 服务器 |
| 审核机制（防违规内容 —— 这类游戏的内容风险不低） | ❌ |
| 版本兼容（游戏更新了，老模组还能用吗） | ❌ 这是最麻烦的一个 |

> **判断**：创意工坊是**平台级功能，不是游戏功能**。它排在路线图的最后一段 —— **游戏本身得先成立，才谈得上让别人给它做内容。**

### 6.4 内容从哪来（最容易低估的问题）

**这是本作最大的风险，而且它不是技术问题。**

一局 20 分钟，玩家大概会遇到 **15–25 个节点**。如果重开 5 次还不腻，至少需要 **60–80 个不重复的节点**。要真正耐玩，需要几百个。

**写一个节点要多久？** 一段 100 字的文本 + 2–4 个选项 + 每个选项的后果 —— 认真写一个，半小时。**80 个节点 = 40 小时纯写作**，还不算调平衡。

**三条可能的出路**（都要在未来验证）：

| 出路 | 说明 | 风险 |
|---|---|---|
| **① 节点池 + 随机组合** | 节点不完全串成线，而是从池子里按条件抽取 → **80 个节点能组合出远超 80 条的体验** | 可能让故事显得散 |
| **② 只做一个时代、一种人生** | 不做"从古到今的所有人"，只做"某个年代的一类人" | 内容量小了，但也牺牲了广度 |
| **③ 让玩家贡献内容** | 就是创意工坊 —— 长期看这是唯一能真正解决内容量的办法 | 需要平台，很远 |

> **第一版选 ① + ②：节点池 + 收窄到一个时代的一种人生。**
> 这也是"一个人做得出来"的前提。

### 6.5 世代传承（记入路线图，第一版不做）

太吾绘卷最动人的机制：你死了，你的孩子接着，血脉一代代传下去。

**它为什么好**：把"一个人的一生"变成"一个家族的历史"，情感厚度立刻翻倍。

**为什么第一版不做**：它要求"上一代的数值和选择会影响下一代"（遗传、家产、名声），这是**在核心循环上再加一层循环**。地基还没打好就盖二楼。

## 八、第一版（MVP）设想

**前提：这份设想只是"存档"，不是"计划" —— 什么时候做，见第九节。**

| 项目 | 第一版做什么 |
|---|---|
| **页面** | **1 个页面**：上方数值面板 / 中间文本区 / 下方选项按钮 |
| **时代** | **只做一个时代**（待定）的一种人生 |
| **出身** | 3–5 种，只影响初始数值 + 少量专属节点 |
| **节点数** | 40–60 个，用"节点池 + 条件抽取"组合 |
| **数值** | 6 个：健康 / 金钱 / 心情 / 关系 / 名声 / 能力 |
| **随机** | 有权重，但**关键节点必出现**（不能随机掉人生大事） |
| **存档** | 一个存档位，能接着玩 |
| **结算** | 结尾给一段"你的一生"总结 + 引用若干关键选择（回声机制） |
| **界面** | 文字 + 按钮，**加一条最小演出层**：立绘插槽 + 运镜 + 文字动效 + 音效 |
| **演出** | **2–3 个关键节点**做完整演出（含 **1 个会动的角色**做验证），其余节点用简化演出；素材靠**复用 + 组合**，不给每个节点配专属画面（见第十三节） |
| **技术** | 与「今日热搜」同样的路线：HTML + CSS + 原生 JS，数据放数据文件（**内容与引擎分离**）；**演出脚本同样是数据** |
| **成功标准** | ① **玩一次 15 分钟，能玩出 3 种明显不同的结局，并且想再开一局**；② **至少有一个选择之后的演出让人"想截图"** |

### 第一版绝对不做的事

| 不做 | 为什么 |
|---|---|
| 创意工坊 / 模组系统 | 平台级功能，需要游戏本体先稳定 |
| 世代传承 | 在核心循环上再加一层循环，地基不够 |
| NPC 关系网、世界自己运转 | 太吾绘卷和 CK3 都证明这是工业级投入 |
| 地图、军队、外交 | 那是《钢铁雄心》，不是本作 |
| 多时代、多国家、多文明 | 内容量爆炸，一个人写不完 |
| ~~图片、立绘、动画、音效~~ → 修订为：**美术量的堆砌**（给每个节点配一套专属画面） | ⚠️ **这条已按第十三节修订**：**不是不做演出，是不做"一个节点一套专属素材"**。第一版要做一条**最小演出层**，素材靠复用组合 |
| 账号、云存档、排行榜 | 需要后端 |
| 移动端适配 | 先把桌面版做透 |
| 多语言 | 同上 |

## 十二、工作分工与学习路径

> 这一节回答两个问题：
> ① 真要做这款游戏，**哪些事 AI 能替我做，哪些必须我自己来**？
> ② 在那之前，**我该学什么、不该学什么**？

### 12.1 先说结论

> **技术部分大概占 20–30%，这部分 AI 基本能包。**
> **内容和手感大概占 70%，这部分 AI 只能给草稿。**
>
> 一句话：**AI 是产能，不是判断力。**

AI 能把"写代码"这件事的**速度**提高十倍，但它**不能替你决定这个游戏该长什么样**，也**不能替你判断它好不好玩**。

### 12.2 逐项分工

| # | 要做的事 | AI 能做什么 | 我必须做什么 |
|---|---|---|---|
| 1 | **技术框架**（读取节点、判断条件、跳转、渲染） | ✅ **基本全包**，需求说清楚就能给出可运行的代码 | 说清楚需求；**看懂代码在干什么** —— 不然将来改不动 |
| 2 | **数据结构设计**（剧情文件长什么样） | ⚠️ 能给 2–3 个方案和各自取舍 | **拍板选哪个** —— 这是判断，不是生成 |
| 3 | **界面与样式** | ✅ 能写，也能按反馈改到满意 | 决定"什么样的界面算顺眼" |
| 4 | **剧情文本初稿** | ✅ 能批量产出，给一段设定能写 20 个节点 | **定方向、审改、删掉不对味的** —— AI 写的东西常常"看着对，但不是那个味" |
| 5 | **数值与平衡** | ⚠️ 能算、能按指令改参数 | **必须自己反复试玩** —— AI 感觉不到难度曲线 |
| 6 | **节奏与手感**（什么时候该给事件、文本多长合适） | ❌ **做不了** | **只有玩过几十遍的人才知道** |
| 7 | **"这游戏该是什么样"的方向判断** | ❌ **做不了** | 能拍板的只有我 |
| 8 | **长期一致性**（世界观、语气、人物不飘） | ⚠️ 单次能对齐，跨度一大就会漂 | 攒一份**设定圣经**，每次让 AI 按它写；发现飘了就拉回来 |
| 9 | **"不好玩"之后的重构** | ⚠️ 能执行重构 | **得先看出哪里不好玩，并决定往哪改** |
| 10 | **持续驱动**（今天写 5 个节点，明天再写 5 个） | ❌ 它不会主动催我 | **只有我能坚持** |

### 12.3 AI 明确做不到的四件事

| # | 做不到的 | 为什么 |
|---|---|---|
| 1 | **替我判断"该做什么样的游戏"** | 它没有偏好。你问它"第一版做哪个时代"，它会给你三个都不错的方案 —— 决定权还在你手里 |
| 2 | **替我试玩、替我感受难度** | 它不能真正"玩"。**"这个选择太狠了""这段太啰嗦了"这类判断，只有玩的人知道** |
| 3 | **替我长期保持一致** | 每次对话它都从头开始。跨度一大，语气和世界观就会漂 —— 得靠一份写死的设定文件兜住 |
| 4 | **替我坚持** | 内容量是这款游戏最大的坎，而这个坎只能靠"每天写一点"跨过去 |

> 反过来说也一样：**这四件事恰恰是我必须亲自参与的部分** ——
> 而它们正好就是这款游戏"好不好玩"的全部来源。**这其实是好消息**：
> AI 拿走的是最枯燥的那部分（搭架子、查语法、写样板），留下的是最有趣的那部分（做决定、编故事、试玩）。

### 12.4 学习路径：五个阶段

```
阶段①  现在 ────────→ 28 天课程
阶段②  课后 1–3 个月 ──→ 把 JS 练熟 + 玩透同类游戏
阶段③  3–6 个月 ───────→ 数据结构 + 状态管理
阶段④  6–12 个月 ──────→ 做一个 20 节点的小原型
阶段⑤  之后 ──────────→ 扩内容 → 再谈平台
```

| 阶段 | 时间 | 学什么 | 过关标准 |
|---|---|---|---|
| **① 打地基** | 现在（28 天课程） | HTML / CSS / JS 三件套；完整走一遍 **研究 → PRD → 技术设计 → 动手** 的流程 | 三个网站做出来并上线 |
| **② 练手感** | 课后 1–3 个月 | 把 JS 练到"不查资料也能写 判断 / 循环 / 函数 / 数组对象"；**同时玩透 2–3 款同类游戏** | 能说清 BitLife 的数值系统是怎么设计的 |
| **③ 学结构** | 3–6 个月 | **数据结构**（嵌套的对象和数组怎么组织）+ **状态管理**（"现在处于哪个状态、能往哪走"） | 能白纸画出"节点 → 选择 → 数值 → 下一节点"的存储结构 |
| **④ 做原型** | 6–12 个月 | **做一个 20 节点的小原型** —— 不追内容量，只验证"核心循环成不成立"；**同时开始学 Live2D Cubism Editor，做出第 1 个会动的角色** | 能连玩 5 局不觉得无聊（或：**明确知道是哪里无聊**）；能自己做 1 个会动的角色 |
| **⑤ 再扩大** | 之后 | 扩内容、调平衡、**把静态立绘逐个换成会动的模型**，最后才谈创意工坊 | 见第九节路线图 |

**关于阶段④的特别说明**：20 个节点是**故意做小的**。
理由和「今日热搜」先做 30 条一模一样 —— **用最小成本验证方向，方向错了就换，别闷头做一年才发现不好玩。**

### 12.5 明确"不用学"的东西（省下来的都是时间）

| 不用学 | 为什么 |
|---|---|
| **Python** | 除非将来要写工具批量处理剧情文件，否则用不上。本作从开发到游玩，全程在浏览器里就能完成 |
| **C++ / C#** | 那是做 3D 大作和游戏引擎的语言。本作是"文字 + 按钮"，用不上 |
| **Unity / Unreal 这类游戏引擎** | 🔑 **这条最容易走错。** 一听到"做游戏"，第一反应往往是"那得去学 Unity"。但 Unity 是给"要有 3D、要物理效果"的项目准备的。**本作连第 3 档（会动的角色）在网页上都能跑完，仍然不需要它**。只有哪天真要做第 4 档实时 3D，才需要重新评估 —— 那是很远的事 |
| **后端 / 服务器 / 数据库** | 第一版是**单机游戏**，存档用浏览器自带的本地存储就够（和"今日热搜"能纯静态跑起来是同一个道理）。只有做创意工坊（上传下载模组）才需要后端 —— 那是很后面的事（见 6.3） |
| **绘画 / 手绘 / 3D 建模** | 🔄 **这条已修订**：**不用自己画**（素材交给 AI 生成 + 后期处理），但**也不是完全不用学** —— 第 3 档的核心工具是 **Live2D Cubism Editor**（不是编程，是美术工具）。见第十三节 |
| **游戏引擎的一切术语** | ECS、Shader、物理引擎…… **现在一个都不用管** |

### 12.6 一条原则：做中学，别学完再做

**从课程前几天的经验看**：Day 1 学的东西当天就用上了；Day 5 写完技术设计，"数据流"这个词才真正懂。
**编程这件事是先做再懂，不是先懂再做。**

所以上面五个阶段**不是"学完了才能进下一阶段"**：

> 阶段③的"数据结构"，很可能在你做阶段④原型的过程中才真正懂；
> 阶段②的"玩透同类游戏"，你现在就能做 —— 但**现在不做**。

### 12.7 提醒：课程期间只做一件事

| | |
|---|---|
| ⛔ **现在只做一件事** | **把 28 天课程做好**。游戏相关的一切（包括"先去玩几款同类游戏"）都**先不做** |

## 十三、表现层与演出设计

> **这一节记录一个重要补充**：本作**不只是文字游戏** —— 玩家每做出一个选择，要有对应的演出。
>
> 原话：「每当做出一个选择，会有相对应的动画剧情。」
>
> **为什么必须单独写一节**：它推翻了第八节原来的两条限制（"不做图片动画音效"），也改写了 12.5 的两条结论。**不写清楚，三个月后自己会看不懂当初为什么改。**

### 13.1 先分清两层（否则会和第一节打架）

第一节写着「**不是视觉小说**」。那句话说的是**剧情结构**（不是选 A 看一段、选 B 看一段的线性分支），**不是"不许有画面"**。

| 层 | 管什么 | 这次 |
|---|---|---|
| **系统层**（骨架 = 玩法） | 节点 / 选项 / 数值 / 权重 | **不动**（见第四节） |
| **表现层**（皮肤 = 演出） | 画面 / 立绘 / 运镜 / 音效 / 文字动效 | **新增 —— 本节的主题** |

> **一句话分工**：**系统决定"发生什么"，表现决定"看起来有多带感"。**

### 13.2 演出也是「数据」

继续 6.3 那条原则（内容与引擎分离）。一段"选择之后的演出"应该写成**脚本**，而不是写进代码：

```
选择"参军" →
  画面切到火车站（淡入 1 秒）
  立绘从左滑入，表情"不舍"
  屏幕轻微震动 0.5 秒
  BGM 淡出，音效：汽笛
  文字逐字显示
```

| 谁 | 负责 |
|---|---|
| **引擎** | "**会**放动画"：淡入、滑入、震屏、音效这些能力 |
| **脚本** | "**放什么**"：这一场用哪张背景、什么表情、停多久 |

好处和 6.3 完全一样：**加剧情不用改代码**；将来别人做模组，也只需要写脚本。

### 13.3 目标档位（已拍板）

「动画剧情」这个词能指的东西差别极大 —— 从几乎不花钱，到一个人绝对做不出来：

| 档位 | 长什么样 | 需要什么 | 一个人做得到吗 |
|---|---|---|---|
| **第 1 档** | 文字动效：打字机、淡入淡出、震屏 | 纯代码，零素材 | ✅ 现在就能做 |
| **第 2 档** | 静态画面 + 运镜：背景切换、立绘进出场、镜头推拉 | 背景图 + 立绘（AI 可生成） | ✅ 可行，素材是主要工作量 |
| **第 3 档** | **角色会动**：表情变化、肢体动作、口型 | 分层立绘 + Live2D 建模 | ⭐ **本作的目标档位**（一人可做，但慢） |
| **第 4 档** | 实时 3D 演出（像《底特律：变人》） | 引擎 + 建模 + 动画团队 | ❌ 一个人做不出来 |

**已拍板的结论**：

- ⭐ **第 3 档 = 起步目标** —— 每做出一个选择，画面里的角色真的会动、会换表情
- ⏳ **第 4 档 = 远期想法**。等前 3 档都跑通、并且这件事已经不只是"一个人"在做的时候，**再重新评估工具链**（到那时才会讨论要不要上引擎）
- 第 1、2 档**不是被放弃，而是第 3 档的地基**（见 13.6）

### 13.4 第 3 档的工具链（2026-09-22 核实）

| 问题 | 事实 |
|---|---|
| 网页上能跑吗 | ✅ 能。**Live2D 官方提供 Cubism SDK for Web**（用 JS / WebGL 渲染）—— 仍然是 HTML + JS 那一套，**不需要 Unity** |
| 要花多少钱 | 开发测试阶段**不需要任何许可**。正式发布时，**年销售额低于 1000 万日元的个人或小规模作者可免除许可费与协议**（"可扩展性应用程序"除外，以官网为准） |
| 文件体积 | 一个会动的角色**只有几 MB** —— 比"视频方案"（一段几十 MB）轻得多。**这是第 3 档比"AI 生成视频"更现实的关键原因** |
| 制作工具 | Cubism **Editor** 有免费版可用；PRO 为订阅制，学生有折扣 |

> ⚠️ **授权条款会变，上面只记大意**。真要发布前必须重新查一遍官网 —— 这条属于第十节那类"动手前要重新验证"的信息。

### 13.5 真正的门槛：不是代码，是做模型

**这是最容易低估的地方。**

| # | 要做的事 | 难在哪 |
|---|---|---|
| 1 | **准备分层立绘（PSD）** | 头发 / 眉毛 / 眼睛 / 嘴 / 脸颊 / 手臂 / 身体 要**各自独立成层**。⚠️ **AI 生成的图通常是拼合的一整张，不能直接用来建模** —— 需要先拆层（有 AI 辅助工具，但效果不稳定，仍需人工修） |
| 2 | **在 Cubism Editor 里建模** | 给图层绑变形器和参数（眨眼 / 张嘴 / 转头 / 呼吸）。**新手第一个角色可能要几十小时**，做熟后几小时 |
| 3 | **保持一致** | 一个会动的角色，脸在 80 个场景里必须**始终是同一个人**。这比静态图的要求更苛刻 |

### 13.6 🔑 关键设计：立绘插槽

**这一条决定了前面所有分工不会白做。**

> **演出脚本只写"动作"，不写"用哪张图"。** 那个位置做成一个**插槽**：
>
> - 第一版：插槽里放**一张静态立绘**（几小时就能备好）
> - 第二版：插槽里换成 **Live2D 模型**（会动）
> - **演出脚本一行都不用改**

```
演出脚本（数据）                立绘插槽
"立绘滑入，表情=不舍"   ──→   ├ 第一版：静态立绘（一张图）
"屏幕震动 0.5 秒"             └ 第二版：Live2D 模型（会动）
```

**由此得到正确的做事顺序**：

| 步骤 | 做什么 | 目的 |
|---|---|---|
| ① | 用**静态立绘**先把游戏跑起来（素材几小时备好） | 尽快回答最根本的问题：**核心循环好不好玩** |
| ② | 同时开始学 Cubism Editor，做第一个角色（几十小时） | 掌握工具 |
| ③ | 模型做好，**插进插槽** | 验证"活起来"值不值这几十小时 |

> ⚠️ **顺序反了的代价**：如果一上来就死磕 Live2D 模型，可能**花了几十小时、还没玩过自己的游戏一次**。
> 模型不会白做，但"游戏好不好玩"这个最关键的答案，会晚好几个月才出现。
>
> **先让游戏能玩，再让它好看。**

### 13.7 组合式演出（解决"素材永远不够"）

> **不需要"每个选择都独一无二"，需要的是"感觉上独一无二"。**

做法：**素材复用 + 组合**。

| 素材 | 数量 |
|---|---|
| 背景 | 5 张 |
| 角色 | 4 个 |
| 每个角色的表情 | 3 种 |
| 运镜模板 | 几套（推、拉、横移、抖动） |
| 文字速度 / 停顿节奏 | 可调 |

再叠上音效与 BGM 的搭配 —— 组合出的演出种类**远多于素材数量**。

玩家记住的是"我参军那次火车开走了"，**不会去数背景图用的是第几张**。

### 13.8 AI 生成素材的三个硬限制

**"不是有 AI 能生成视频吗" —— 部分可以，但撑不起"每个选择都现场生成"。**

| 限制 | 具体是什么 |
|---|---|
| **一致性** | 同一个角色在 50 张图、80 段视频里能长得一样吗？AI 目前很不可靠 —— 要靠"角色设定图"反复约束 + 人工挑，**成功率可能只有几分之一** |
| **体量** | 80 个节点 × 每段 10 秒 = 13 分钟视频。网页上堆这么多视频，文件可能几个 G，**加载不动**（改用 Live2D 后这条基本消失：一个角色只有几 MB） |
| **成本** | 每一段都要花时间和额度。80 段视频不是 80 次点击，是**几百次尝试 + 几十小时筛选** |

**AI 生成真正适合的位置**：

| | |
|---|---|
| ✅ **适合** | 片头 / 宣传片；**人生大事类关键节点**（结婚、战争、死亡）；立绘与背景图的**批量初稿**（再人工修 + 拆层） |
| ❌ **不适合** | 给每个普通选择现场生成 |

### 13.9 第一版的演出范围

| 项目 | 第一版做什么 |
|---|---|
| **演出层** | 立绘插槽 + 背景切换 + 运镜 + 文字动效 + 音效（第 1、2 档的能力全部具备） |
| **做完整演出的节点** | **2–3 个关键节点**，其余节点用简化演出 |
| **会动的角色** | **1 个** —— 用来验证"值不值"，不是全角色铺开 |
| **素材策略** | 复用 + 组合（见 13.7），**不给每个节点配专属画面** |
| **验证目标** | ① 演出能不能让人"想截图"？② 插槽设计对不对 —— 静态图换成 Live2D 是不是真的零改动？ |

> 这和"20 节点原型"是同一个思路：**最小成本验证方向**。
> **演出是加分项，不是救命稻草** —— 核心循环不好玩，演得再炫也留不住人。

### 13.10 本节的不确定信息

| # | 不确定的事 | 现在凭什么这么写 |
|---|---|---|
| 1 | "新手几十小时做出第一个角色"是否准确 | 来自公开教程的普遍说法，未亲身验证 |
| 2 | Live2D Web SDK 与"演出引擎"的对接难度 | 没写过，可能比想象中麻烦（模型加载、参数控制、与脚本时间轴同步） |
| 3 | **"组合式演出"会不会看起来重复** | 没试过。**这是本节最大的假设** |
| 4 | AI 拆层工具的实际效果 | 听说可用，未实测 |
| 5 | 12.1 那个"技术 20–30% / 内容手感 70%"的比例 | ⚠️ **需要按演出层重新估算** —— 做模型是第三种工作，既不算写代码，也不算写剧情 |
| 6 | 第 4 档到底做不做、什么时候做 | 完全未知，先不作承诺 |
