## 〇、这个站有几个页面（Day 13 更新：三页结构）

**三个独立的 HTML 页面，靠超链接跳转：**

| # | 文件 | 页面 | 里面有什么 |
|---|---|---|---|
| 1 | `index.html` | **门户首页** | 形象图案（墨日 + 飞鸟 + 远山）+ 融合搜索框 + 两个入口按钮 |
| 2 | `hot.html` | **热点速览** | 30 条热搜列表 + 筛选 + 收藏 + 四种状态（这是网站的主体） |
| 3 | `trend.html` | **热度趋势分析** | 示例数据的示意曲线（诚实标注"示例数据"）+ 未来功能占位 |

**跳转关系：**

```
门户首页 index.html
   ├── 点「热点速览」按钮 ──→ hot.html
   ├── 搜索框输入 + 回车 ──→ hot.html?kw=关键词（自动预填并筛选）
   └── 点「热度趋势分析」──→ trend.html
hot.html / trend.html 顶部都有「← 返回首页」
```

**为什么选"多 HTML 文件"而不是"前端路由"**：纯静态站、零框架，多文件最直观——
每个页面就是一个看得见摸得着的文件，样式 `style.css` 三页共用。
地址路由（`/hot` 这种）列入"下一步计划"，不阻塞。

## 一、怎么打开（两种方式，任选）

### 方式 A：双击打开（最快，推荐日常用）

**直接双击 `index.html`**，浏览器就会打开（会先看到门户首页，点「热点速览」进列表）。

- ✅ 优点：不用命令行、不用装东西、改一行双击就能看效果
- ⚠️ 注意：这样打开时，**地址栏显示的是 `file:///D:/...`**，不是 `localhost`

### 方式 B：起一个本地服务器（地址栏是 localhost）

**Windows 上打开「命令提示符」或「PowerShell」，粘贴下面这行命令**（需要电脑装了 Python）：

```
cd /d "D:\Vibe coding\Project\Hot-search" && python -m http.server 8788
```

**看到这样的输出就成功了**：

```
Serving HTTP on 0.0.0.0 port 8788 (http://0.0.0.0:8788/) ...
```

**然后在浏览器地址栏输入**：

```
http://localhost:8788
```

- ✅ 优点：地址栏是 `localhost` 开头；将来发布到网上时，行为与本地服务器一致
- ⚠️ 注意：**这个窗口不能关** —— 关了服务就停了。要停止服务，在那个窗口按 `Ctrl + C`

> 💡 **两种方式的区别**：方式 A 是"直接把文件丢给浏览器"，方式 B 是"先起一个小服务器，浏览器再向它要文件"。效果看起来一样，但方式 B 更接近网站正式发布后的真实情况。

## 二、怎么验证它做对了（照着点一遍）

打开页面后，按顺序试这几件事：

| # | 怎么做 | 应该看到什么 |
|---|---|---|
| 1 | 打开页面 | 直接显示 **30 条**热点，按热度从高到低排列，编号 **01 ~ 30** |
| 2 | 看每条的内容 | 每条有 **4 样**：排名、标题、来源平台、热度值（如「微博 · 热度 98.7万」） |
| 3 | 在输入框里打「**手机**」 | 列表**立刻**只剩 1 条，编号重编成 **01**，上方提示「筛出 1 条（共 30 条）」 |
| 4 | 再打「**微博**」 | 列表变**空** —— 显示「没有找到相关内容」。**这不是 bug**，是故意的：筛选只匹配标题，而「微博」只出现在来源平台字段里 |
| 5 | 把输入框清空 | 恢复显示全部 30 条，顺序和一开始一样 |
| 6 | 输入框里**只敲空格** | 仍然显示全部 30 条（空格视为空，不触发空状态） |
| 7 | 随便点一条 | **新窗口**打开百度搜索结果页，搜索词就是这条的标题；原来那个页面不动 |

**第 4 条要特别记一下** —— 它是这个项目最重要的一个验收点（`PRD.md` 验收标准 B2）。

### 再看看四种"页面状态"（Day 8 新增）

一个页面不只有"有数据"这一种样子。它一共有 **四种状态**，都要处理：

| 状态 | 什么时候出现 | 页面显示什么 |
|---|---|---|
| ⏳ **加载中** | 打开页面后的头 0.6 秒 | 转圈动画 + 「正在加载热点…」 |
| ✅ **有数据** | 数据拿到了 | 卡片列表 |
| 📭 **空** | 筛了关键词但没匹配到（比如搜「微博」） | 「没有找到相关内容」 |
| ⚠️ **出错** | 数据没拿到（本地开发几乎不出现） | 红色提示 + 具体原因 + 「重新加载」按钮 |

**为什么要专门处理这四种**：因为只做"有数据"这一种，用户遇到另外三种时会看到**一片空白**，分不清是"还在加载"还是"坏了"。

**怎么亲眼看到这四种状态**（Day 9 更新：不用改代码了，用网址参数即可）：

| 想看的 | 在网址后面加 | 例子 |
|---|---|---|
| ⏳ 加载中 | `?slow=8`（把等待拉长到 8 秒） | `http://localhost:8788/?slow=8` |
| 📭 空 | 搜一个不存在的词，或加 `?empty=1` | `http://localhost:8788/?empty=1` |
| ⚠️ 出错 | `?fail=1` | `http://localhost:8788/?fail=1` |
| ✅ 正常 | 不加任何参数 | `http://localhost:8788/` |

> 💡 这几个参数写在 `app.js` 的 `DEBUG` 里，是**开发专用**的。
> 将来接上真后端，这段直接删掉，其余逻辑一个字都不用改。

> ⚠️ **「出错」状态是最容易被漏掉的一个** —— 因为在自己电脑上开发，网络从来不抖，这个状态几乎不出现。但上线以后用户网络一差就会撞上。所以**必须写、必须测**。

> 💡 **遇到"改了代码但页面没变"怎么办**：
> 浏览器会缓存 js 和 css。最可靠的办法是给网址挂个版本号
> （`index.html` 里现在是 `app.js?v=3`），每次改动把数字加一，浏览器就会重新下载。
> 其次才是按 `Ctrl + Shift + R` 强制刷新。

## 三、界面是什么风格（Day 9 更新：水墨国风）

整站换成**水墨国风**。不是贴几张水墨图片，而是**用 CSS + SVG 画出来的**：

| 元素 | 做法 |
|---|---|
| **宣纸底** | 冷白浅灰的底纸 + 多层极淡的墨晕，模拟墨在纸纤维里渗开 |
| **墨色文字** | 不用纯黑，按国画「墨分五色」分层：焦墨（标题）/ 浓墨（正文）/ 重墨（次要）/ 淡墨（提示）/ 清墨（线条） |
| **朱砂印章** | 题头右上角一枚红方印「热搜」；前三名的排名序号也是朱砂墨点 |
| **毛笔竖条** | 每张卡片左侧一道渐变竖条 —— 起笔重、中段轻、收笔散 |
| **字体** | 宋体/楷体优先，横细竖粗，有笔锋感；字距拉宽，像落款的疏朗 |
| **配色克制** | 全站只有两个彩色：朱砂红（重点）+ 石青（次要标签），其余都是墨与纸 |

**为什么不用图片素材**：水墨图如果做成图片文件，双击打开时可能加载失败，而且体积大。
**纯 CSS + SVG = 零依赖、零体积、改一行颜色整站跟着变。**

配色全部收在 `style.css` 开头的 `:root` 变量里 —— 想调整色调，只改那十几行。

### 色调是怎么一步步调深的

一共调了三版，记录一下思路（不是简单调暗，而是**把反差拉开**）：

| 版本 | 纸 | 墨 | 问题 / 变化 |
|---|---|---|---|
| 第一版 | 米黄（`#f4f1e9`） | 松烟墨 | 偏"旧书页"，用户说要**水墨色** |
| 第二版 | 冷白生宣（`#f2f3f4`） | 分层更细 | 去掉了黄气，但用户要**更深更浓** |
| 第三版 | 浅灰（`#d8dbdf`） | 焦墨近黑 | **纸压深 → 墨才跳得出来**；卡片反而改成纯白，与灰底强反差 |

### 「墨水在纸上晕染」是怎么做出来的（Day 9 四改版）

用户要求：**要体现出墨水在纸上晕染的感觉**。真墨在纸上扩散有三个特征，都用 CSS/SVG 伪造（零图片）：

| 特征 | 怎么实现 | 用在哪 |
|---|---|---|
| **① 浓度递减**（中心实、越往外越稀） | 多层 `radial-gradient` / 内阴影 | 卡片、搜索框、状态框 |
| **② 形状不规则**（边缘一鼓一鼓） | SVG 三次贝塞尔画墨迹轮廓 + `feTurbulence` 位移 + `feGaussianBlur` 揉毛 | 题头的泼墨 |
| **③ 水痕边**（最外圈留一道痕） | 同一个轮廓再描一遍，只在 72%~86% 处上色 | 题头的泼墨 |

> ⚠️ **这里返工了三次，教训值得记**：
> 1. 只用 CSS 渐变堆 → 出来是**一片均匀的灰雾**，像屏幕脏了（渐变都是标准椭圆，形状太规矩）
> 2. 把不透明度拉高 → 灰度够了，但还是"一块模糊的色块"
> 3. 改成 **SVG 画真实墨迹轮廓** → 才真的是"一坨有形状的墨"
>
> 还有一个坑：**文字会被墨吃掉**。
> 解法来自国画 —— 题字压在墨上时要**留白**，
> 所以给标题加了 `text-shadow` 白色轮廓（从里到外：1px 白线 → 4px 白晕 → 7px 留白带），把字从墨里"抠"出来。

### 两侧的国风装饰（Day 9 追加）

内容区是 720px 居中，宽屏时两侧会空出大片留白，所以在两侧各加了一列竖向装饰：

| 位置 | 元素（从上到下） |
|---|---|
| **左** | 回纹 → 梅花枝 → 竹枝 → 竖排「人间烟火气 · 最抚凡人心」→ 太湖石 → 水波纹 |
| **右** | 回纹 → 兰花 → 折扇 → 竖排「一日看尽 · 天下事」→ 朱砂闲章「观」→ 松枝 → 祥云纹 |

**元素全是 CSS + 内联 SVG 画的**（回纹用 `repeating-linear-gradient`，其余用 SVG 线条），同样零图片依赖。

三个关键设计：

1. **不挡鼠标**：装饰层设了 `pointer-events: none`，纯背景，不会影响你点卡片
2. **窄屏自动隐藏**：屏幕小于 1240px 时（装不下内容区 + 两侧装饰）自动隐藏，
   手机上也看不到 —— 所以它**只在宽屏存在，永远不会挤到内容**
3. **有墨韵**：每个图案背后垫一层 `filter: blur()` 的模糊同色，线条保持清晰、背后是洇开的墨
   （⚠️ 第一版是给图案**本身**加模糊，结果糊成一团灰啥都看不清 —— 方向反了）

> 💡 想换诗句？改 `index.html` 里 `.deco-verse` 内的 `<span>` 即可，一个字一个标签。

## 四、文件都是干什么的

| 文件 | 职责 | 一句话 |
|---|---|---|
| `index.html` | 页面骨架 | 页面上有哪些东西（题头、输入框、列表容器、四个状态块） |
| `style.css` | 页面长相 | 配色变量、宣纸底、墨色文字、印章、卡片样式、转圈动画 |
| `data.js` | **数据** | 30 条示例热点（标题 / 来源平台 / 热度值） |
| `app.js` | **逻辑** | 取数 → 排序 → 算排名 → 渲染 → 筛选 → 点击跳转 → 管四种状态 |

**加载顺序**（在 `index.html` 底部）：`data.js` → `app.js`
（先有数据，再有处理数据的逻辑）

### `app.js` 里的两个"零件"（Day 8 新增）

写法上把界面拆成了两个**可复用的小组件**，而不是写一堆零散的拼接代码：

| 函数 | 作用 | 类比 |
|---|---|---|
| `createHotCard(item, index)` | 造出**一条**卡片 | 造一块积木 |
| `createHotList(list)` | 造出**一整列**卡片 | 把积木拼成一排 |

好处：以后要加个"收藏按钮"或改卡片长什么样，**只改造积木那一个函数**，30 条卡片一起变。

## 五、几条要记住的设计约定

### 1. 取数只写在一个地方

`app.js` 里的 `fetchHotList()` 是**唯一**拿数据的地方。

- **现在**：它从 `data.js` 的 `HOT_LIST` 拿
- **将来**：改成向服务器要数据（`fetch('/api/hot')` 之类），**只改这一个函数**

排序、渲染、筛选那些逻辑**一行都不用动**。

> 🔑 它在 Day 8 被改成了**异步**的（返回 Promise，会等一小会儿才有结果）。
> 这不是多此一举 —— 真实网络请求本来就是"发出去、等一会儿、可能失败"。
> **现在就把结构摆成这样，将来接后端时，外面所有调用代码都不用改。**

### 2. 数据里不存排名

排名是 `app.js` **算出来的**（因为筛选之后要重新编号）。
数据里存了它反而会和计算结果打架。

### 3. 热度值只用来排序

不宣称"全网热度"。因为**各平台的数值口径完全不同，不可跨平台比较**。
页面上已经标明了这批是**示例数据**。

### 4. 为什么数据是 `data.js` 不是 `data.json`

因为**双击打开网页时（`file://`），浏览器不许网页读本地文件** —— 用 `.json` 页面会白屏。
写成 `.js`，数据就随页面一起加载，不受这个限制。

> 代价：将来换真实数据时，要多改约 3 行代码。但那正好落在第 1 条说的"取数只写在一个地方"，改动范围很小。

## 六、Day 10 修掉的一个真实问题：页面会撒谎

> 这是这个项目里**第一个真正"用户会撞上"的 bug** —— 不是样式不好看，是**说了假话**。

### 症状

网速慢的时候，数据还在路上，用户先在搜索框里打了字，于是：

1. **它把"还没到"说成"没有"** —— 页面立刻跳成「没有找到相关内容」，还配一个「空」字方框。
   可数据压根没到，它一次都没搜过。
2. **等数据到了，它又把用户的话忘了** —— 搜索框里明明还写着关键词，页面却把全部 30 条哗哗排出来。

### 病根（就一处）

`app.js` 里**没有一个"数据到没到"的记号**，所以两条路各走各的：

| 谁 | 干了什么蠢事 |
|---|---|
| `applyFilter()`（输入时触发） | 手里还是空数组也照筛 → 筛出 0 条 → 当成"世界上没有" |
| `loadData()`（数据到达时触发） | 到了就喊「显示全部」，**看都没看搜索框** |

### 怎么改的（只动 `app.js` 三处）

| 改动 | 说明 |
|---|---|
| 新增 `let dataReady = false` | 一个"数据到没到"的记号，初始是"没到" |
| `applyFilter()` 开头加 `if (!dataReady) return;` | 数据没到 → 直接不干活，让"加载中"继续显示 |
| `loadData()` 里把 `showState('list', …)` 换成 `applyFilter()` | 数据到了不再自己喊"显示全部"，改为**叫筛选器来定**：框里没字就显示全部，有字就筛 |

**核心是把两条路并成一条** —— 数据到达后统一走 `applyFilter()`，
以后不用再担心"取数"和"筛选"两边各说各话。

> ✅ 顺带堵住了同一个 bug 的另一面：**出错页面上打字**，以前会把错误提示顶掉、
> 变成「没有找到相关内容」；现在错误提示稳稳留着。

**影响面**：`index.html` / `style.css` / `data.js` **一个字没碰** ——
这正是第五条第 1 项「取数只写在一个地方」那条约定带来的好处：**问题也集中在一个地方**。

### 怎么验证的

复现步骤固定为「数据未到 → 打字 → 等数据到」，修复前后各跑一遍：

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 加载途中打字 | 「没有找到相关内容」（撒谎） | 「正在展卷」（老实） |
| 数据到达后 | 30 条全排出来（无视搜索框） | 筛出 4 条（听话） |

另外回归了正常列表 / 空状态 / 出错状态，均正常。

## 七、四个交互（Day 11 新增）

站里现在有四件"点一下就有反应"的事。它们都不联网、不依赖后端，
所有动作都发生在你自己的浏览器里。

| # | 交互 | 在哪 | 点了之后你看到什么 |
|---|---|---|---|
| ① | **复制链接** | 每条右边的「复制」 | 按钮上的字变成「已复制」，同时变朱砂色；1.6 秒后自己变回去 |
| ② | **收藏星标** | 每条右边的星星 | 星星填实变朱砂、弹一下（像盖了个章）；顶部「只看收藏」的数字跟着 +1 |
| ③ | **展开详情** | 每条右边的箭头 | 卡片下方展开一块，列出**同一来源**还有哪几条上榜，以及原始热度数字；箭头翻身朝上 |
| ④ | **回到顶部** | 右下角（滚远了才出现） | 平滑滚回页面顶部，按钮随即自己隐去 |

另外配了一个小开关：**只看收藏**（在搜索框下面那行右边）。
收藏过东西之后点它，列表就只剩收藏的那几条。

### 三条写在代码里的规矩

**1. 点了必须有反应，而且反应要看得见。**
按钮变色、文字换成「已复制」、星星弹一下 —— 都是在回答用户没问出口的那句话：
「我这一下，你听见了吗？」
用户点了没反应，就会以为坏了，然后再点一次（然后就成了连点）。

**2. 卡片里的小按钮，必须拦住点击往外传。**
卡片本身是个大按钮（点一下打开搜索），小按钮就住在它怀里。
如果不拦，点「复制」会连带把搜索窗口也弹出来。
代码里的 `makeCardButton()` 专门处理这件事 —— `click` 和键盘 `keydown` 两条路都拦。

**3. 一次只开一个详情。**
几张卡片同时展开的话，下面的内容会被顶得到处跑，很容易点错。
所以每次展开前，先把别的合上。

### 手快连点，也不会乱

这一条专门测过 —— 因为"点得快"最容易暴露问题：

- **连点收藏 4 次**（间隔 0.3 秒，比动画还短）：最终状态和点击次数完全对得上，没丢、没错
- **连点复制**：「已复制」的倒计时会重新计时，不会出现"第二次点没反应"

> 两个技术上的小机关写在 `app.js` 里：
> 复制要用 `clearTimeout` 清掉上一个倒计时；
> 星星的动画重播要先摘掉 class、强制浏览器重排一次（读一下 `offsetWidth`），否则同一段动画不会播第二遍。

### 收藏存在哪？

存在**你自己浏览器的本地存储**（localStorage）里。
关掉浏览器再打开还在，**不会上传到任何服务器**。

> ⚠️ 它是按网址隔离的：用本地服务器打开时的收藏、和双击打开文件时的收藏，
> 是两个互不相通的"抽屉"。这是浏览器的规矩，不是 bug。

### 键盘也能用（不用鼠标）

这一版把键盘这条路也走通了：

| 按键 | 作用 |
|---|---|
| `Tab` | 依次走过：搜索框 → 只看收藏 → 每条卡片 → 复制 → 收藏 → 展开 → 下一条 |
| `Enter` / `空格` | 等于"点一下"当前选中的东西 |
| 焦点提示 | 键盘走到哪，哪里就亮起一圈**朱砂色细框**（鼠标点不会触发它，只有键盘会） |

> 调试小开关：网址后面加 `?focus=1`，打开时光标会自动落进搜索框，
> 按 Tab 就能从头一路验过去。

### 关于"用真实数据"这件事

**现在是示例数据，不是真的。** 原因有两条：

1. **法律**：抓取微博/知乎/百度等平台的数据，违反它们的服务条款
2. **技术**：纯静态网页没有后端，浏览器**不允许**网页直接去别的网站抓数据（同源策略）

**正确的做法**是：**加一个后端，让后端定时去取数据，前端向后端要数据**。
`TECH_DESIGN.md` §5.4 已经把这条路的图景画好了，也说明了"换数据源时前端几乎不用改"。

**这一步排在 28 天课程结束后**（见 `PRD.md` §5.4 路线图）。
