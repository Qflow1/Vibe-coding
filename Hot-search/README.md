## 一、怎么打开（两种方式，任选）

### 方式 A：双击打开（最快，推荐日常用）

**直接双击 `index.html`**，浏览器就会打开。

- ✅ 优点：不用命令行、不用装东西、改一行双击就能看效果
- ⚠️ 注意：这样打开时，**地址栏显示的是 `file:///D:/...`**，不是 `localhost`

### 方式 B：起一个本地服务器（地址栏是 localhost）

**Windows 上打开「命令提示符」或「PowerShell」，粘贴下面这行命令**（需要电脑装了 Python）：

```
cd /d "D:\Vibe coding\Project\Hot-search" && python -m http.server 8788
```

**看到这样的输出就成功了**：

```
Serving HTTP on 0.0.0.0 port 8788 (http://0.0.0.0:8788/) ...
```

**然后在浏览器地址栏输入**：

```
http://localhost:8788
```

- ✅ 优点：地址栏是 `localhost` 开头；将来发布到网上时，行为与本地服务器一致
- ⚠️ 注意：**这个窗口不能关** —— 关了服务就停了。要停止服务，在那个窗口按 `Ctrl + C`

> 💡 **两种方式的区别**：方式 A 是"直接把文件丢给浏览器"，方式 B 是"先起一个小服务器，浏览器再向它要文件"。效果看起来一样，但方式 B 更接近网站正式发布后的真实情况。

## 二、怎么验证它做对了（照着点一遍）

打开页面后，按顺序试这几件事：

| # | 怎么做 | 应该看到什么 |
|---|---|---|
| 1 | 打开页面 | 直接显示 **30 条**热点，按热度从高到低排列，编号 **01 ~ 30** |
| 2 | 看每条的内容 | 每条有 **4 样**：排名、标题、来源平台、热度值（如「微博 · 热度 98.7万」） |
| 3 | 在输入框里打「**手机**」 | 列表**立刻**只剩 1 条，编号重编成 **01**，上方提示「筛出 1 条（共 30 条）」 |
| 4 | 再打「**微博**」 | 列表变**空** —— 显示「没有找到相关内容」。**这不是 bug**，是故意的：筛选只匹配标题，而「微博」只出现在来源平台字段里 |
| 5 | 把输入框清空 | 恢复显示全部 30 条，顺序和一开始一样 |
| 6 | 输入框里**只敲空格** | 仍然显示全部 30 条（空格视为空，不触发空状态） |
| 7 | 随便点一条 | **新窗口**打开百度搜索结果页，搜索词就是这条的标题；原来那个页面不动 |

**第 4 条要特别记一下** —— 它是这个项目最重要的一个验收点（`PRD.md` 验收标准 B2）。

## 三、文件都是干什么的

| 文件 | 职责 | 一句话 |
|---|---|---|
| `index.html` | 页面骨架 | 页面上有哪些东西（标题、输入框、列表容器） |
| `style.css` | 页面长相 | 颜色、间距、字号 |
| `data.js` | **数据** | 30 条示例热点（标题 / 来源平台 / 热度值） |
| `app.js` | **逻辑** | 取数 → 排序 → 算排名 → 渲染 → 筛选 → 点击跳转 |

**加载顺序**（在 `index.html` 底部）：`data.js` → `app.js`
（先有数据，再有处理数据的逻辑）

## 四、几条要记住的设计约定

### 1. 取数只写在一个地方

`app.js` 里的 `getAllData()` 是**唯一**拿数据的地方。

- **现在**：它从 `data.js` 的 `HOT_LIST` 拿
- **将来**：改成向服务器要数据，**只改这一个函数**

排序、渲染、筛选那些逻辑**一行都不用动**。

### 2. 数据里不存排名

排名是 `app.js` **算出来的**（因为筛选之后要重新编号）。
数据里存了它反而会和计算结果打架。

### 3. 热度值只用来排序

不宣称"全网热度"。因为**各平台的数值口径完全不同，不可跨平台比较**。
页面上已经标明了这批是**示例数据**。

### 4. 为什么数据是 `data.js` 不是 `data.json`

因为**双击打开网页时（`file://`），浏览器不许网页读本地文件** —— 用 `.json` 页面会白屏。
写成 `.js`，数据就随页面一起加载，不受这个限制。

> 代价：将来换真实数据时，要多改约 3 行代码。但那正好落在第 1 条说的"取数只写在一个地方"，改动范围很小。

### 关于"用真实数据"这件事

**现在是示例数据，不是真的。** 原因有两条：

1. **法律**：抓取微博/知乎/百度等平台的数据，违反它们的服务条款
2. **技术**：纯静态网页没有后端，浏览器**不允许**网页直接去别的网站抓数据（同源策略）

**正确的做法**是：**加一个后端，让后端定时去取数据，前端向后端要数据**。
`TECH_DESIGN.md` §5.4 已经把这条路的图景画好了，也说明了"换数据源时前端几乎不用改"。

**这一步排在 28 天课程结束后**（见 `PRD.md` §5.4 路线图）。
