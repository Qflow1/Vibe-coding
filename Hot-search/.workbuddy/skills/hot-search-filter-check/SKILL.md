# 热搜网站筛选检查

## Overview

本 skill 用于检查「今日热搜」网站（`Hot-search/` 目录，纯静态 HTML+CSS+JS）的
**关键词筛选**是否工作正常。它列出一套固定步骤，按顺序走一遍，就能确认筛选的
三种情况（有结果 / 无结果 / 清空恢复）都没有问题，并顺带核对结果与提示文字
是否对得上。

## 什么时候用

- 用户说「检查筛选」「验证筛选」「测一下搜索框」。
- 改动了 `app.js` 里 `applyFilter`、`showState`、`updateHint` 等函数，需要回归。
- 交接或上线前，想快速确认筛选这条核心功能没坏。

## 需要先知道的三件事（背景）

1. **筛选逻辑只有一个出口**：`app.js` 里的 `applyFilter()`。输入、点「只看收藏」、
   数据到达后，最终都走它。所以检查筛选，重点就是盯着这个函数的三种走向。
2. **三种情况**（本 skill 的核心检查点）：
   - **有结果**：输入一个确实能命中的词 → 列表只显示命中的条目
   - **无结果**：输入一个不存在的词 → 显示「空」状态（标题「没有找到相关内容」）
   - **清空恢复**：把关键词删光 → 列表恢复显示全部条目
3. **数字要对得上**：顶部提示（`#filterHint`）写的「筛出 N 条（共 M 条）」，
   和实际列出的卡片数、以及数据总量 M，三者必须一致。

## 检查步骤（按顺序，一条条过）

### 第 1 步：确认页面能正常加载

打开 `http://127.0.0.1:8788/?v=<最新版本号>`（本地服务器），或双击 `index.html`。

- **通过标准**：等约 1 秒后，看到卡片列表（默认 30 条），顶部提示「共 30 条」。
- **如果卡在「正在展卷」或「出错了」**：先别往下查筛选，去查数据加载
  （`data.js` 的 `HOT_LIST` 在不在、`fetchHotList` 有没有报错）。

### 第 2 步：测「有结果」

在搜索框输入一个肯定能命中的词（数据里已有的，例如「城市」「AI」「大学」）。

- **通过标准**：
  - 列表只剩命中词的那些条目，且按热度从高到低排。
  - 顶部提示变成「筛出 N 条（共 30 条）」，N = 实际卡片数。
  - 排名序号从 01 重新编号。

### 第 3 步：测「无结果」

输入一个不存在的词（例如 `zzzz`、`qqqq` 这类肯定不在标题里的）。

- **通过标准**：
  - 列表消失，换成「空」状态框，标题是「没有找到相关内容」。
  - 顶部提示是「没有匹配的内容」。

### 第 4 步：测「清空恢复」

把搜索框里的字**全部删掉**（清空）。

- **通过标准**：
  - 列表恢复显示全部 30 条，顶部提示回到「共 30 条」。
  - 没有残留上一次的筛选结果。

### 第 5 步：核对「提示文字」和「页脚」

- 顶部提示（`#filterHint`）的数字要和实际列出的卡片数一致。
- ⚠️ **已知的小瑕疵**：页脚写死「共 30 条示例数据」，筛选后**不会**跟着变
  （这是 `index.html` 里的静态文字，不是 bug，是"文字写错了地方"）。
  如果哪天要修，改 `app.js` 让页脚也走 `updateHint` 的逻辑，而不是去改 `index.html`。

### 第 6 步（可选，余力加练）：可访问性抽查

- 搜索框要有可读的标签或 `placeholder`（本项目有 placeholder，够用）。
- 用键盘 `Tab` 能否走到搜索框、能否输入、回车后筛选是否生效。
- 空状态/出错状态是否只靠颜色区分（如果是，需要补文字，因为色盲用户看不到）。

## 检查记录模板

每次检查后，把结果填进下面这个表，作为「调用记录」存档：

```
| 检查项 | 结果 | 看到的证据 |
| 页面加载 | ✅/❌ | ... |
| 有结果筛选 | ✅/❌ | ... |
| 无结果筛选 | ✅/❌ | ... |
| 清空恢复 | ✅/❌ | ... |
| 提示数字核对 | ✅/❌ | ... |
```

## 一句话说清本 skill 检查了什么

**本 skill 检查的是：关键词筛选在「有结果 / 无结果 / 清空恢复」三种情况下是否
正确，以及筛选结果和顶部提示、实际卡片数是否对得上。**
